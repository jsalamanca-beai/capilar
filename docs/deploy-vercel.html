Deploy en Vercel

Guia paso a paso para poner la app en produccion

⏱️
Tiempo total: ~15 minutos. Necesitas: cuenta Vercel (gratis), cuenta Supabase (gratis), API key de OpenAI. El repo ya esta en GitHub.
Prerequisitos
0

Antes de empezar

Lo que necesitas tener
  • Cuenta en GitHub con acceso al repo jsalamanca-beai/capilar
  • Cuenta en Vercel (crear en vercel.com si no tienes — gratis con GitHub)
  • Cuenta en Supabase (crear en supabase.com — gratis)
  • API key de OpenAI (platform.openai.com — de pago, ~5 EUR para empezar)
  • (Opcional) Token de Telegram bot (gratis, ver docs/setup-telegram.html)
Paso 1: Supabase
1

Crear proyecto en Supabase

Base de datos + almacenamiento de fotos
~5 min

1a. Ve a supabase.com/dashboard → New Project

  • Nombre: capilex-patient-app
  • Region: West EU (Ireland) (la mas cercana a Madrid)
  • Password: genera una segura y guardala

1b. Espera ~2 minutos a que se cree. Luego ve a Settings → API y copia:

# Lo encuentras en Settings → API
NEXT_PUBLIC_SUPABASE_URL = https://xxxxxxxxxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY = eyJhbGciOiJIUz...

# Lo encuentras en Settings → API → service_role (mostrar)
SUPABASE_SERVICE_ROLE_KEY = eyJhbGciOiJIUz...
⚠️
NUNCA compartas el service_role key. Es la clave con permisos totales sobre la BD. Solo va en variables de entorno del servidor (Vercel), nunca en el codigo.

1c. Ejecutar las migraciones SQL. Ve a SQL Editor en Supabase y ejecuta en orden:

  1. Pega y ejecuta el contenido de supabase/migrations/001_initial_schema.sql
  2. Pega y ejecuta supabase/migrations/002_seed_protocol.sql
  3. Pega y ejecuta supabase/migrations/003_seed_notification_templates.sql
✅
Verificacion: En Table Editor deberias ver 20 tablas creadas (clinics, patients, interventions, etc.) y datos de seed en care_protocols, protocol_task_items, protocol_medication_items y protocol_shopping_items.

1d. Crear el bucket de almacenamiento de fotos. Ve a Storage → New Bucket:

  • Nombre: patient-photos
  • Public: NO (privado)
  • File size limit: 10 MB
  • Allowed MIME types: image/jpeg, image/png, image/webp
Paso 2: Crear paciente de prueba
2

Insertar datos de prueba

Un paciente con una intervencion para testear
~2 min

En el SQL Editor de Supabase, ejecuta:

-- Paciente de prueba INSERT INTO patients (id, clinic_id, first_name, last_name, email, phone) VALUES ( 'a0000000-0000-0000-0000-000000000001', '00000000-0000-0000-0000-000000000001', 'Jose', 'Salamanca', 'jose@test.com', '+34600000000' ); -- Intervencion con codigo de acceso -- Cambia la fecha para simular el dia postoperatorio que quieras INSERT INTO interventions ( patient_id, protocol_id, clinic_id, access_code, surgery_date, status, grafts_count, technique, surgeon_name ) VALUES ( 'a0000000-0000-0000-0000-000000000001', '00000000-0000-0000-0000-000000000010', '00000000-0000-0000-0000-000000000001', 'TEST1234', CURRENT_DATE - INTERVAL '5 days', -- Simula dia 5 postop 'post_op', 2500, 'FUE', 'Dr. Martinez' );
💡
Tip: Cambia CURRENT_DATE - INTERVAL '5 days' para simular diferentes dias. Usa + INTERVAL '3 days' para simular pre-operatorio (cirugia en 3 dias).

Codigo de acceso para entrar: TEST1234

Paso 3: Deploy en Vercel
3

Importar proyecto en Vercel

Conectar GitHub → Vercel
~3 min

3a. Ve a vercel.com/new

3b. Selecciona "Import Git Repository"

3c. Busca y selecciona el repo jsalamanca-beai/capilar

3d. Configuracion del proyecto:

  • Framework Preset: Next.js (se detecta automaticamente)
  • Root Directory: ./ (raiz)
  • Build Command: dejar por defecto (next build)
  • Output Directory: dejar por defecto

3e. En la seccion "Environment Variables", anade TODAS estas:

Variable Valor Estado
NEXT_PUBLIC_SUPABASE_URL https://xxxx.supabase.co Obligatoria
NEXT_PUBLIC_SUPABASE_ANON_KEY eyJhbGci... Obligatoria
SUPABASE_SERVICE_ROLE_KEY eyJhbGci... Obligatoria
OPENAI_API_KEY sk-proj-... Obligatoria
JWT_SECRET (genera 32+ chars aleatorios) Obligatoria
CRON_SECRET (genera 32+ chars aleatorios) Obligatoria
TELEGRAM_BOT_TOKEN 7123456789:AAH... Opcional
TELEGRAM_CLINIC_CHAT_ID -1001234567890 Opcional
🔑
Generar JWT_SECRET y CRON_SECRET: Abre la terminal y ejecuta:
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
Ejecutalo 2 veces (una para cada secret).

3f. Pulsa "Deploy" y espera ~2 minutos.

✅
Si el deploy es exitoso, Vercel te dara una URL tipo capilar-xxxx.vercel.app. Esa es tu app en produccion.
Paso 4: Dominio personalizado
4

Configurar dominio (opcional)

app.capilexmadrid.es en vez de xxxx.vercel.app
~5 min

4a. En Vercel, ve a tu proyecto → Settings → Domains

4b. Escribe: app.capilexmadrid.es y pulsa Add

4c. Vercel te mostrara un registro DNS que debes crear:

# Anadir en el panel DNS de tu proveedor de dominio:
Tipo: CNAME
Nombre: app
Valor: cname.vercel-dns.com

4d. Espera a que propague (5 min - 24h). Vercel genera certificado SSL automaticamente.

💡
Si no tienes dominio propio: La URL de Vercel (capilar-xxxx.vercel.app) funciona perfectamente. Puedes configurar el dominio despues.
Paso 5: Verificar
5

Verificar que todo funciona

Checklist de verificacion post-deploy
~3 min
  • Abrir la URL de Vercel → se ve la pagina de inicio con logo Capilex
  • Ir a /login → introducir TEST1234 → redirige al dashboard
  • Ver el contador de dias postoperatorio correcto
  • Ir a /checklist → ver tareas del dia
  • Ir a /medications → ver los 4 medicamentos
  • Ir a /shopping → ver los 8 items
  • Ir a /chat → enviar un mensaje → recibir respuesta del agente IA
  • Ir a /photos/upload → subir una foto → ver analisis IA
  • Ir a /emergency → ver telefono y email de la clinica
🎉
Si todo funciona, la app esta en produccion! Cada push a main en GitHub desplegara automaticamente en Vercel.
Despliegues automaticos
6

Actualizaciones futuras

CI/CD automatico con GitHub

Cada vez que hagas push a main, Vercel despliega automaticamente:

# Desde tu maquina local:
git add .
git commit -m "feat: nueva funcionalidad"
git push origin main

# Vercel detecta el push y despliega en ~2 min

Tambien puedes ver el estado de cada deploy en vercel.com/dashboard.

Troubleshooting
?

Problemas comunes

Si algo no funciona
Problema Solucion
Build falla en Vercel Verifica que todas las env vars obligatorias estan configuradas. Ve a Deployments → click en el deploy fallido → ver logs.
Login dice "Codigo no encontrado" Verifica que ejecutaste el SQL del paso 2 en Supabase. El codigo es TEST1234 (mayusculas).
Chat no responde / error IA Verifica que OPENAI_API_KEY es valida y tiene credito. Ve a platform.openai.com/usage.
Fotos no se suben Verifica que creaste el bucket "patient-photos" en Supabase Storage (paso 1d).
Telegram no envia Verifica TELEGRAM_BOT_TOKEN y TELEGRAM_CLINIC_CHAT_ID. El bot debe ser admin del grupo.
Error 500 en API Ve a Vercel → Functions → Logs para ver el error detallado.
Cron jobs no se ejecutan Los cron jobs solo funcionan en Vercel Pro ($20/mes) o con un servicio externo tipo cron-job.org.
💡
Cron gratis alternativo: Si usas Vercel Hobby (gratis), los cron jobs no estan disponibles. Puedes usar cron-job.org (gratis) para llamar a tus endpoints /api/cron/daily-summary con el header Authorization: Bearer TU_CRON_SECRET.
